# Sparse virtual shadow maps

`<vulkanizer/svsm.hpp>` provides directional, software-paged virtual shadows. The
library owns the page cache and GPU culling; applications own their scene,
geometry, animation, materials, and draw submission. It does not require an ECS,
scene graph, `vkz::mesh`, bindless registry, or a particular object buffer layout.

## Device and resource contract

Use Vulkan 1.3 with dynamic rendering and synchronization2 enabled, and enable
`VkPhysicalDeviceFeatures::fragmentStoresAndAtomics` at device creation. Set
`params::fragment_stores_and_atomics_enabled` to acknowledge that it was enabled.
Creation checks physical support, R32_UINT storage-image atomic support, and
configuration limits. No floating-point atomic extension is used. The shadow
fragment helper converts finite [0,1] float depth to unsigned integer bits and
uses `imageAtomicMin` (`OpAtomicUMin` in SPIR-V). Negative zero is canonicalized.

Default storage is 1024 128x128 pages (64 MiB) shared between six 8192x8192 virtual
clipmaps. The actual square atlas rounds capacity up to a square number of pages;
`physical_pages` remains the usable allocation count. A clipmap doubles its world
width at each level. `first_clipmap_extent` is full width, not radius.

Receiver depth is a borrowed single-sample, sampled 2D image in a readable layout.
Supply the inverse of the exact view-projection matrix used to rasterize it,
including camera jitter. UV and the matrix must use Vulkan's positive-height
viewport convention. Reverse-Z receiver depth is supported by supplying the
appropriate inverse matrix and `background_depth=0`. Shadow depth itself is
always conventional [0,1]. Integer receiver formats, array views, and MSAA depth
are not supported. Accepted views use a Vulkan depth format or R16F, R32F,
RGBA16F, or RGBA32F color data.

The light direction points in the direction light travels. `light_depth_min/max`
are world-space dot-product limits along its normalized direction, not camera
near/far planes. Include upstream, off-screen shadow casters in this interval.
Keep it fixed where possible: changes invalidate the cache. Light rotation also
invalidates the cache. Rebase large worlds before float projection precision
becomes insufficient, and reset after rebasing.

## Supplying casters

Each `caster_bounds` is a 48-byte, 16-byte-aligned record:

| Offset | GLSL | Meaning |
|---|---|---|
| 0 | vec4 | World-space AABB center in xyz |
| 16 | vec4 | Conservative half extent in xyz |
| 32 | uvec4 | Opaque application metadata; x may hold an application ID |

Visibility uses the **input record index**, not the opaque ID. A record is a
drawable unit: an instance, submesh, terrain patch, cluster, or shadow proxy.
One record can enclose an instanced draw, but then the entire instance group is
culled together. The application must include all relevant casters, not just
objects visible to its main camera. Bounds must enclose deformation/displacement.

`frame_inputs::casters` is a tightly packed STORAGE_BUFFER. It can be uploaded
from any CPU object representation or generated by application compute shaders.
There is no CPU readback in the frame pipeline. Inputs and optional draw templates
must remain alive until the frame completes. Buffer offsets are currently zero;
use a dedicated buffer or copy/adapt from an application arena.

The GPU projects AABBs with center/extent arithmetic, rejects against light-space
coverage, and intersects the projected page rectangle with an OR hierarchy of
pages scheduled for this frame. The hierarchy is in clipmap-local coordinates,
so toroidal page-table wrapping cannot turn a rectangle into an incorrect range.
Traversal is bounded and retains objects conservatively on overflow. No camera
occlusion test is used. Output is a uint array `[clipmap][caster_count]`.

## Frame recording

```cpp
auto shadows = vkz::svsm::create({
    .device = device,
    .memory_allocator = allocator,
    .max_casters = max_drawables,
    .fragment_stores_and_atomics_enabled = true,
});

// After the receiver depth prepass, outside any rendering scope:
vkz::svsm::begin(shadows, cmd, {
    .depth = readable_depth,
    .inverse_view_projection = glm::inverse(raster_view_projection),
    .camera_position = camera_position,
    .light_direction = sun_direction,
    .light_depth_min = -500,
    .light_depth_max = 500,
    .frame_slot = slot,
    .casters = caster_bounds_buffer,
    .caster_count = drawable_count,
    .indexed_draws = draw_templates,
});

vkz::svsm::capture(shadows, cmd, [&](const vkz::svsm::render_context& pass) {
    // Application binds vertex/index buffers and material descriptors here.
    // Bind a custom compatible shadow pipeline for skinning/alpha testing, or
    // use the already bound opaque pipeline (vec3 position, stride 12).
    for (uint32_t i = 0; i < pass.caster_count; ++i) {
        vkz::svsm::draw_constants push;
        push.model = my_drawables[i].world;
        push.clipmap = pass.clipmap;
        push.caster_index = i;
        vkCmdPushConstants(cmd, pass.default_layout,
            VK_SHADER_STAGE_VERTEX_BIT | VK_SHADER_STAGE_FRAGMENT_BIT,
            0, sizeof(push), &push);
        vkCmdDrawIndexedIndirect(cmd, pass.indexed_draws,
            pass.indexed_draw_offset + i * sizeof(VkDrawIndexedIndirectCommand),
            1, sizeof(VkDrawIndexedIndirectCommand));
    }
});
vkz::svsm::end(shadows, cmd);
// Now shade receivers using descriptor_set(shadows, slot) and svsmSample().
```

`indexed_draws` is optional. If present, supply one tightly packed
`VkDrawIndexedIndirectCommand` per caster with STORAGE_BUFFER usage. The library
preserves every field except it zeroes `instanceCount` for rejected casters.
Outputs have STORAGE_BUFFER, INDIRECT_BUFFER, and TRANSFER_SRC usage. Bind the
correct geometry and descriptors for each command/batch. Multi-draw and nonzero
indirect firstInstance require the corresponding device features if used by the
application. The example above uses one indirect command per call.

A generic renderer can consume `visibility()` in its own draw generation instead
of using the indexed adapter. Direct draws can use the default vertex shader's
visibility check, but still incur vertex invocation cost. A CPU callback runs
while recording: it cannot directly iterate a same-frame GPU visibility list.

The callbacks run inside attachmentless dynamic rendering, once per clipmap. Do
not start another rendering scope inside them or modify the library's internal
buffers. They must render all accepted geometry for the scheduled pages. After
clearing a dirty page, unchanged geometry on that page must be redrawn as well.
An empty callback is valid only for an empty scene/empty pages.

## Custom shaders and lighting

The installed `vulkanizer/shaders/svsm.glsl` is the integration include. Add the
installed include directory to the application's GLSL compiler search paths.
`SVSM_SET` selects the descriptor set number (default zero). The set layout is
returned by `descriptor_set_layout()`. Do not change its binding definitions.

For a custom caster vertex shader, transform deformed world positions with
`svsm.light[clipmap]`. Interpolate virtual UV = clip XY * 0.5 + 0.5. Define
`SVSM_WRITE` before including the helper in the fragment shader, perform material
alpha testing, then call `svsmStore(clipmap, virtualUV, depth + bias)`.
Physical coordinates are translated per fragment, never interpolated. Use one
sample, no framebuffer attachments, and explicit shader bias: there is no depth
attachment to provide normal fixed-function depth testing/bias.

For lighting, include the helper without `SVSM_WRITE` and call
`svsmSample(worldPosition, receiverBias)`. It returns `(visibility, coverage)`.
Coverage zero means no valid data at any covering level; visibility defaults to
one. Manual PCF uses the frame's radius (0..4), resolves each virtual tap
individually, and falls back as a whole kernel to a coarser valid level.

## Cache and scheduling

The frame pipeline resets transient flags, requests pages from receiver depth,
invalidates changed bounds, allocates/schedules coarse levels first, clears only
scheduled physical pages, builds the page hierarchy, culls, renders, then
publishes completed pages as valid. Page tags retain logical coordinates, not
just wrapped indices. Sub-page camera movement preserves cached data.

The allocator is a deterministic single-invocation GPU baseline, with bounded
pool scans and no CPU readback. It retains unused pages until eviction is needed.
Coarse demand can evict finer cached pages to preserve fallback coverage. Pool
capacity and render budget are hard limits; undersized configurations may still
have uncovered receivers. Inspect `statistics::missing` and sampling coverage.
`rendered` counts scheduled pages, including pages cleared to an empty sky value.

Supply changed bounds in `invalidations` before begin:

- Movement: old and new bounds as separate records.
- Deletion: old bounds.
- Insertion: new bounds.
- Skinning, displacement, alpha-mask/material changes, shadow LOD changes:
  affected old/new conservative coverage, even if the transform did not change.

Changes are projected at all levels without restricting invalidation by receiver
depth. Rebuilding a page considers every current caster. `reset()` or
`reset_cache` invalidates everything. `params::cache=false` regenerates requested
pages each frame. Camera-dependent deformation requires invalidation as well.

## Synchronization and lifetime

Call begin/capture/end on the same command buffer, once per frame, in actual
submission order on one graphics+compute queue. Wait for a frame slot before
updating its descriptor set/input buffers or reusing its scratch resources.
Flush noncoherent host uploads. GPU-written inputs on the same queue are covered
by begin's dependency; external queues require application semaphores and
ownership transfers. Depth must already be in its supplied readable layout.

The shared atlas/page table are persistent across slots. Prepare orders updates
after all earlier queue reads and writes, including previous lighting reads.
Finish makes raster writes and validity changes visible to subsequent shading
and diagnostic transfer reads. All use of the cache must follow this queue
order; separate slots do not permit concurrent access from independent queues.

Borrowed descriptors/resources must not be destroyed by consumers. Finish GPU
work before destroy. If abandoning a recorded frame, explicitly reset before
recording its replacement; submit order must remain consistent. Calls require
external CPU synchronization (including the instance registry).

## Bistro integration and checks

Build `vulkanizer_svsm_test` and `vulkanizer_svsm_bistro`. Run the small GPU
regression with CTest:

```powershell
ctest --test-dir cmake-build-debug -C Debug -R vulkanizer_svsm_test --output-on-failure
.\cmake-build-debug\test\Debug\vulkanizer_svsm_bistro.exe --validation
```

The viewer uses a 4096-page (256 MiB) pool and a 1024-page update budget; the
library defaults remain 1024 pages. It uses vendored tinyobjloader v2.0.0rc13 (MIT), groups material draws
within each OBJ shape, subdivides them into bounded caster batches, and supports
alpha-tested diffuse materials in the camera and shadow passes. Diffuse textures
have mipmaps. Vista's diffuse/irradiance cubemaps provide the sky and ambient light.
The specular cubemap is copied for future material experiments but is not used.

Local resources (deliberately ignored by Git):

- `test/resources/bistro/`: exterior/interior OBJ+MTL and all three extracted
  texture directories, copied from `Z:\Downloads\bistro`. Redundant ZIP archives
  were not copied.
- `test/resources/svsm_skybox/`: three `skybox_*.ktx` files copied from Vista.

Use `--obj <file>`, `--scale <factor>` (default 0.01), and `--skybox <directory>`
to select other local copies. `--frames N`, `--timeout seconds` (after loading),
and `--screenshot output.png` support repeatable smoke runs. WASD/QE and left-drag
control the camera. The UI exposes light direction, cache reset/forced
invalidation, visibility/coverage views, and GPU page counters.

Enable **Physical page atlas** (or launch with `--physical-pages`) to overlay the
physical address texture in slot order. Orange tiles were rendered this frame
(new allocations or refreshes), green tiles are requested cache hits, blue tiles
are retained but not requested, dark tiles are free, red tiles are invalid, and
purple tiles are outside the configured physical capacity. Moving the camera
shows slots being released and reused; the existing eviction counter reports
reclaimed pages. **Stored depth** displays the actual uint-bit-decoded shadow
depth inside each resident valid tile, retaining its state color around the edge.
The overlay reads GPU state after `end()` without a CPU readback. Launch with
`--physical-depth` to select the stored-depth view immediately.

Custom debug shaders can define `SVSM_DEBUG` before including `svsm.glsl` to read
`svsmOwners` at binding 10. Each entry maps a physical slot to a `svsmPages` index,
or `SVSM_NONE` for a free slot. `SVSM_RENDERED` identifies pages completed by the
current `end()` and is cleared by the next `begin()`.

Current boundaries: one directional light per instance; fixed-size software
pool; no light-space Hi-Z, draw compaction, cropped raster viewport, hardware
sparse binding, or static/dynamic cache separation. Geometry is rasterized once
per accepted caster/clipmap; fragments outside scheduled pages are discarded by
the store helper. Fine-grained demand for transparency/volumetrics is not yet
exposed; `request_all_pages` is the conservative debug alternative. Profile the
single-thread allocator and full-viewport atomic rasterization before production
deployment, especially for uncached scenes.
